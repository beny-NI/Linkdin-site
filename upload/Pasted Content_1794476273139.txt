# SkilledSphere
## Global Professional Discovery & Editorial Platform
### Complete Product, Design & Technical Implementation Specification

---

# 1. Project Vision

Design and develop a premium, modern, international web platform called **SkilledSphere**.

SkilledSphere is a global professional discovery and editorial platform designed to introduce exceptional professionals, industry experts, researchers, entrepreneurs, executives, founders, and leaders across different industries.

The platform combines three major concepts:

1. **Professional Discovery:** Helping companies, organizations, investors, and individuals discover professionals based on expertise, industry, achievements, and geographic location.
2. **Editorial Media:** Publishing professionally curated profiles, interviews, success stories, leadership features, and industry-related content.
3. **Professional Networking:** Creating opportunities for professionals and organizations to discover each other and establish meaningful business connections.

### Core Product Positioning

SkilledSphere is NOT a LinkedIn clone.

It is not intended to be a social network based on daily posts, likes, comments, follower counts, or connection metrics.

Instead, position it as a curated global professional discovery platform with a premium editorial identity.

**Core Brand Message:**

"Discover the People Shaping What's Next."

The primary audience includes technology professionals, business leaders, researchers, entrepreneurs, engineers, creative professionals, medical specialists, and other recognized experts.

The platform must be international from the beginning, with English as its primary language and an architecture that supports additional languages in the future.

# 2. Brand Identity & Visual Direction

Create a distinctive visual identity combining:

- Bold Technology
- Luxury Corporate Design
- Modern Editorial Design
- Premium Professional Media

The website should feel innovative, prestigious, international, sophisticated, and trustworthy.

- Midnight Navy: #0B1530
- Royal Navy: #172747
- Deep Blue: #263B60
- Champagne Gold: #C6A96B
- Warm White: #F5F3EE

- White and warm off-white provide contrast and readability.

Use modern, highly readable typography.

Recommended:

Use expressive headlines, clear hierarchy, carefully controlled letter spacing, and editorial typography.

## UI Principles

- Clean layouts with generous whitespace.
- Strong visual hierarchy.

- Subtle borders and elegant shadows.
- Smooth transitions and carefully designed hover states.

# 3. Technical Architecture & Technology Stack

Use a modern TypeScript-based architecture.

The recommended stack is:

| Layer | Technology |
|---|---|
| Main Framework | Next.js |
| UI Library | React |
| Programming Language | TypeScript |
| Styling | Tailwind CSS |
| UI Components | shadcn/ui |
| 3D Engine | Three.js |
| React 3D Integration | React Three Fiber |
| 3D Utilities | @react-three/drei |
| UI Animations | Framer Motion |
| Scroll Animations | GSAP + ScrollTrigger |
| CMS & Admin | Payload CMS |
| Database | PostgreSQL |
| Geospatial Extension | PostGIS, when required |
| Initial Search | PostgreSQL Full-Text Search |
| Advanced Search | Meilisearch, when required |
| Media Storage | Cloudflare R2 |
| CDN | Cloudflare CDN |
| Deployment | Vercel or suitable managed infrastructure |

## Architectural Approach

Use a **Modular Monolith** architecture.

Do not introduce microservices, Kubernetes, or unnecessary infrastructure complexity in the initial implementation.

The system should be modular, maintainable, and capable of evolving as the platform grows.

Keep business logic, data access, API functionality, and presentation components logically separated.

### Next.js

Use Next.js App Router.

Requirements:

- Server-side rendering where appropriate.
- Static generation for suitable editorial content.
- Dynamic rendering for frequently updated content.
- SEO-friendly public pages.
- Dynamic professional profile routes.
- Optimized image delivery.
- API integration.
- Proper loading and error states.

Use server components by default and client components only where interactivity is required.

### Payload CMS

Use Payload CMS as the primary content management system.

Integrate Payload with the Next.js application.

Payload must manage:

- Professional profiles.
- Expertise categories.
- Industries.
- Countries.
- Professional collections.
- Editorial stories.
- Featured-professional schedules.
- User-submitted applications.
- Media assets.
- Administrative roles and permissions.

Use Payload's PostgreSQL adapter.

Build reusable collections, relationships, validation rules, access controls, and administrative workflows.

The administration interface should be suitable for non-technical editorial staff.

Do not build a separate administration frontend unless there is a clear requirement.

### PostgreSQL

Use PostgreSQL as the primary database.

Design normalized and maintainable data relationships.

Recommended main entities:

- Users
- Professionals
- Countries
- Cities
- ExpertiseCategories
- Industries
- Collections
- CollectionMembers
- Stories
- FeaturedSchedules
- FeaturedApplications
- MediaAssets

Support many-to-many relationships where professionals belong to multiple expertise categories, industries, or collections.

Use stable identifiers and appropriate indexing.

### Geospatial Data

Support geographic information for professionals.

Recommended fields:

- Country code.
- Country name.
- City.
- Region.
- Latitude.
- Longitude.

PostGIS can be introduced for advanced geographic queries, regional searches, and proximity-based discovery.

Do not make PostGIS a mandatory dependency for simple country-level filtering.

The globe must consume structured geographic data rather than hardcoded frontend information.

### Search

Initially use PostgreSQL Full-Text Search and indexed database queries.

Search should cover:

- Professional names.
- Professional titles.
- Expertise.
- Industries.
- Countries.
- Collections.
- Editorial stories.

Keep the search architecture extensible so Meilisearch can be integrated later without redesigning the entire search experience.

### Media Storage

Use Cloudflare R2 for professional portraits, article images, and other uploaded media.

Implement optimized image delivery, suitable formats, responsive image sizes, and CDN caching.

Never store large media files directly inside the relational database.

### ORM & Data Access

Use Payload's database integration as the primary data-access layer.

Avoid adding Prisma or another ORM unnecessarily.

If independent application modules eventually require direct database access, introduce an additional data-access layer only when justified.

# 5. Homepage — Main Experience

The homepage is the most important part of the project.

Its design should be immersive, visually distinctive, and interaction-driven.

Include:

- Full name.

- Main expertise.
- Industry.
- Country or location.

Administrators should be able to:

- Preview the featured card before publishing.

Support a daily rotation system.

Do not hardcode the featured professional in frontend components.

Use realistic sample data for the initial prototype.

## Section 2: Interactive 3D Global Globe

Create a large, realistic, interactive 3D globe as the central visual identity of the homepage.

Initially, position the globe behind and slightly to the left of the featured-professional card.

### Globe Visual Design

Match the SkilledSphere visual identity.

Use:

- Dark navy and deep blue oceans.
- Subtle country boundaries.
- Elegant geographic outlines.
- Carefully selected gold highlights.
- Subtle illuminated geographic markers.
- Soft atmospheric lighting.
- Sophisticated dark surroundings.

Avoid cartoon-like earth graphics and excessive neon effects.

The globe should rotate slowly and continuously when idle.

Its movement should feel calm, elegant, and cinematic.

### Scroll-Driven Globe Transition

This is a critical interaction.

Implement a coordinated scroll-based transition between the featured-professional hero and the global discovery experience.

Initial state:

- Featured card is prominent.
- Globe is positioned behind the card.
- Globe rotates slowly.

As the user scrolls:

1. The featured card gradually scales down.
2. The card moves backward visually and fades away.
3. The globe gradually increases in size.
4. The globe moves into the foreground.
5. The globe becomes the dominant visual element.
6. The transition feels continuous and cinematic.

Avoid excessive animation or interactions that make scrolling uncomfortable.

Once the transition completes, the globe becomes fully interactive.

### Interactive Country Selection

Users must be able to interact directly with the globe.

Required interactions:

- Rotate the globe using mouse drag or touch gestures.
- Zoom in and out where appropriate.
- Click or tap a country.
- Highlight the selected country.
- Rotate the globe toward a selected country.
- Display a country-specific professional discovery panel.

When a country is selected, open a floating panel on the RIGHT side of the globe.

The panel should contain:

- Country name and flag.
- Number of listed professionals.
- Featured professionals from that country.
- Professional portraits.
- Names and professional titles.
- Main expertise tags.
- Short descriptions.
- Links to individual profiles.
- View All Professionals action.

The panel must feel visually integrated with the globe environment.

Do not make it look like a generic dashboard.

### Geographic Data Management

The globe must connect to structured professional data.

Each professional record must contain geographic information.

When an administrator adds a new professional and assigns a country, that professional should automatically appear in the corresponding geographic discovery results.

Do not require manual editing of the 3D globe whenever a professional is added.

Countries without listed professionals should remain selectable and display an elegant empty state.

Use real geographic boundaries and country identifiers.

### Country Navigation Ticker

Directly below the globe section, create an elegant horizontal country navigation ticker.

Example:

United States · United Kingdom · Germany · France · Canada · Japan · Singapore · Australia · Switzerland

When users click a country:

- The globe smoothly rotates toward that country.
- The selected country becomes highlighted.
- The professional panel opens.
- The country ticker reflects the active selection.

Support manual horizontal scrolling.

The ticker should feel like part of the visual experience rather than a conventional navigation menu.

### Leaving the Globe Section

As the user continues scrolling:

- The globe gradually scales down.
- It moves backward and fades away.
- The country ticker disappears.
- The next homepage section enters naturally.

Use coordinated scroll animations.

The globe must not remain fixed indefinitely or interfere with subsequent sections.

# 16. Motion & Interaction Design

Motion is an important part of the SkilledSphere experience.

Use carefully controlled animations:

- Slow continuous globe rotation.
- Scroll-driven globe transformation.
- Smooth country-selection camera movement.
- Elegant panel transitions.
- Subtle card hover interactions.
- Image transitions.
- Smooth navigation transitions.
- Refined loading states.

### Animation Responsibilities

Use:

**GSAP + ScrollTrigger**
- Scroll-based globe transitions.
- Featured card transformations.
- Pinned sections where appropriate.
- Coordinated multi-element scroll timelines.

**Framer Motion**
- UI component transitions.
- Card interactions.
- Modal and panel transitions.
- Navigation animations.
- Micro-interactions.

**Three.js / React Three Fiber**
- Globe rotation.
- Camera positioning.
- Geographic visualization.
- Lighting and materials.
- Interactive country selection.

Do not let GSAP and Framer Motion simultaneously control the same animated properties of an element.

Avoid unnecessary animations.

Respect reduced-motion preferences.

Provide a graceful static or simplified globe fallback when WebGL is unavailable.

# 19. Accessibility, SEO & Performance

### Accessibility

Follow WCAG 2.2 AA principles.

Include:

- Keyboard navigation.
- Visible focus states.
- Sufficient color contrast.
- Accessible form labels.
- Semantic HTML.
- Reduced-motion support.
- Accessible alternatives for interactive geographic elements.

### SEO

Implement:

- Semantic page structure.
- Search-friendly URLs.
- Metadata.
- Open Graph information.
- Structured data for people, articles, and organizations where appropriate.
- Sitemap.
- Robots configuration.
- Canonical URLs.
- Proper indexability of public professional profiles.

### Performance

Prioritize performance despite the immersive visual experience.

Requirements:

- Lazy-load heavy visual assets.
- Optimize portrait images.
- Dynamically load the 3D globe.
- Avoid blocking initial page rendering.
- Minimize unnecessary React re-renders.
- Optimize scroll animations.
- Provide fallback rendering for low-performance devices.
- Use CDN caching and appropriate cache invalidation.
- Avoid loading unnecessary 3D resources on pages that do not use them.

The globe should not prevent the rest of the homepage from becoming usable.

# 22. Development Quality Requirements

Follow these principles throughout implementation:

1. Use reusable and maintainable components.
2. Use TypeScript types for all important data structures.
3. Avoid unnecessary `any` types.
4. Keep components focused and modular.
5. Separate business logic from presentation.
6. Use structured CMS data rather than hardcoded production content.
7. Implement real interactions rather than decorative buttons.
8. Include appropriate loading, error, and empty states.
9. Validate forms on both client and server.
10. Protect administrative operations with proper authorization.
11. Keep secrets and private credentials on the server.
12. Avoid unnecessary dependencies.
13. Follow Next.js and React best practices.
14. Test important user flows.
15. Keep the codebase ready for future expansion.

If an existing codebase is provided:

- Inspect the existing project before making changes.
- Preserve useful existing architecture.
- Avoid unnecessary rewrites.
- Follow existing coding conventions where appropriate.
