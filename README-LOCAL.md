# SkilledSphere — اجرای لوکال در Ubuntu

این راهنما برای اجرای نسخه فعلی پروژه SkilledSphere روی Ubuntu و از طریق ترمینال VS Code نوشته شده است.

## مشخصات فنی پروژه

- Next.js `16.1.3`
- React `19`
- TypeScript
- Bun برای نصب وابستگی‌ها و اجرای اسکریپت‌ها
- Prisma `6.19.2`
- SQLite
- پورت توسعه: `3000`

## ۱. پیش‌نیازها

ترمینال VS Code را باز کنید (`Ctrl + Shift + ~`) و مطمئن شوید داخل پوشه اصلی پروژه هستید؛ یعنی پوشه‌ای که `package.json` در آن قرار دارد.

```bash
pwd
ls
```

در خروجی باید فایل‌هایی مثل `package.json`، پوشه‌های `src`، `prisma` و `db` را ببینید.

### نصب Bun (فقط بار اول)

ابتدا بررسی کنید Bun نصب است:

```bash
bun --version
```

اگر دستور پیدا نشد، Bun را نصب کنید:

```bash
curl -fsSL https://bun.com/install | bash
```

سپس تنظیمات PATH را در ترمینال فعلی بارگذاری و نصب را بررسی کنید:

```bash
source ~/.bashrc
bun --version
```

در زمان تهیه این راهنما، نسخه‌ای که روی سیستم توسعه نصب و با آن پروژه آماده شد `1.4.4` بود. نسخه نصب‌شده ممکن است متفاوت باشد.

## ۲. نصب وابستگی‌های پروژه

از ریشه پروژه اجرا کنید:

```bash
bun install
```

این دستور وابستگی‌های تعریف‌شده در `package.json` و فایل قفل `bun.lock` را نصب می‌کند. اجرای آن در اولین راه‌اندازی ممکن است زمان‌بر باشد.

## ۳. تنظیم فایل محیطی و دیتابیس

پروژه از SQLite استفاده می‌کند و Prisma آدرس دیتابیس را از متغیر `DATABASE_URL` می‌خواند.

فایل `.env` باید در ریشه پروژه باشد و این مقدار را داشته باشد:

```env
DATABASE_URL="file:../db/custom.db"
```

مسیر بالا نسبت به فایل `prisma/schema.prisma` تفسیر می‌شود و به فایل `db/custom.db` در ریشه پروژه اشاره می‌کند.

اگر فایل `.env` از قبل وجود دارد، فقط مقدار `DATABASE_URL` را اصلاح کنید؛ سایر تنظیمات احتمالی را حذف نکنید.

اگر `.env` وجود ندارد، در ریشه پروژه آن را بسازید و مقدار بالا را داخلش قرار دهید:

```bash
printf '%s\n' 'DATABASE_URL="file:../db/custom.db"' > .env
```

وجود فایل دیتابیس را بررسی کنید:

```bash
ls -lh db/custom.db
```

اگر فایل وجود ندارد، ادامه ندهید؛ نسخه اصلی دیتابیس را از بسته/نسخه معتبر پروژه به پوشه `db` برگردانید. اجرای برنامه بدون دیتابیس صحیح ممکن است باعث خطا یا استفاده از دیتابیس خالی شود.

## ۴. تولید Prisma Client

بعد از نصب وابستگی‌ها و تنظیم `.env` اجرا کنید:

```bash
bunx prisma generate
```

این دستور Prisma Client را بر اساس `prisma/schema.prisma` تولید می‌کند.

## ۵. اجرای پروژه در حالت توسعه

از ریشه پروژه اجرا کنید:

```bash
bun run dev
```

وقتی سرور آماده شد، معمولاً آدرسی مشابه زیر در ترمینال نمایش داده می‌شود:

```text
http://localhost:3000
```

آدرس را در مرورگر باز کنید:

[http://localhost:3000](http://localhost:3000)

ترمینالی را که سرور در آن اجرا شده نبندید. برای متوقف‌کردن سرور، در همان ترمینال `Ctrl + C` بزنید.

## اجرای دفعات بعد

پس از اینکه یک‌بار Bun، وابستگی‌ها، `.env` و Prisma آماده شدند، برای اجرای روزمره کافی است:

```bash
cd /مسیر/پوشه/پروژه
bun run dev
```

سپس `http://localhost:3000` را باز کنید.

اگر پوشه پروژه را در VS Code باز کرده‌اید، معمولاً ترمینال از قبل در مسیر درست قرار دارد و نیازی به دستور `cd` نیست.

## دستورات مفید

| دستور | کاربرد |
|---|---|
| `bun --version` | بررسی نصب Bun |
| `bun install` | نصب وابستگی‌ها |
| `bunx prisma generate` | تولید Prisma Client |
| `bun run dev` | اجرای سرور توسعه |
| `bun run build` | ساخت نسخه production |
| `bun run lint` | اجرای ESLint |
| `bun run db:generate` | معادل اسکریپتی تولید Prisma Client |

## عیب‌یابی سریع

### خطای `bun: command not found`

```bash
source ~/.bashrc
bun --version
```

اگر همچنان پیدا نشد، ترمینال VS Code را ببندید و دوباره باز کنید.

### خطای اتصال یا بازشدن دیتابیس SQLite

این موارد را بررسی کنید:

```bash
grep '^DATABASE_URL=' .env
ls -lh db/custom.db
```

مقدار مورد انتظار در `.env`:

```env
DATABASE_URL="file:../db/custom.db"
```

### خطای Prisma Client

```bash
bunx prisma generate
```

سپس دوباره اجرا کنید:

```bash
bun run dev
```

### پورت 3000 اشغال است

بررسی کنید کدام پردازش از پورت استفاده می‌کند:

```bash
ss -ltnp | grep ':3000'
```

اگر سرور قبلی پروژه هنوز فعال است، به ترمینال آن بروید و `Ctrl + C` بزنید.

## هشدارهای مهم دیتابیس

- فایل `db/custom.db` حاوی داده‌های پروژه است؛ پیش از هر تغییر ساختاری از آن نسخه پشتیبان بگیرید.
- دستور `bun run db:push` در این پروژه به `prisma db push --accept-data-loss` متصل است. این دستور ممکن است باعث حذف داده‌ها شود؛ برای اجرای عادی پروژه آن را اجرا نکنید.
- دستور `bun run db:reset` دیتابیس را بازنشانی می‌کند؛ برای راه‌اندازی معمولی استفاده نکنید.
- اسکریپت `.zscripts/dev.sh` نیز به‌صورت خودکار `bun run db:push` را اجرا می‌کند. برای اجرای معمول و امن لوکال، از دستور مستقیم `bun run dev` که در این راهنما آمده استفاده کنید.

## خلاصه اجرای سریع

```bash
bun install

bun run dev
```

سپس مرورگر:
