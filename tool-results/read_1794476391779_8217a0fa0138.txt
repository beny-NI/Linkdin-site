     6→
     7→# 1. Project Vision
     8→
     9→Design and develop a premium, modern, international web platform called **SkilledSphere**.
    10→
    11→SkilledSphere is a global professional discovery and editorial platform designed to introduce exceptional professionals, industry experts, researchers, entrepreneurs, executives, founders, and leaders across different industries.
    12→
    13→The platform combines three major concepts:
    14→
    15→1. **Professional Discovery:** Helping companies, organizations, investors, and individuals discover professionals based on expertise, industry, achievements, and geographic location.
    16→2. **Editorial Media:** Publishing professionally curated profiles, interviews, success stories, leadership features, and industry-related content.
    17→3. **Professional Networking:** Creating opportunities for professionals and organizations to discover each other and establish meaningful business connections.
    18→
    19→### Core Product Positioning
    20→
    21→SkilledSphere is NOT a LinkedIn clone.
    22→
    23→It is not intended to be a social network based on daily posts, likes, comments, follower counts, or connection metrics.
    24→
    25→Instead, position it as a curated global professional discovery platform with a premium editorial identity.
    26→
    27→**Core Brand Message:**
    28→
    29→"Discover the People Shaping What's Next."
    30→
    31→The primary audience includes technology professionals, business leaders, researchers, entrepreneurs, engineers, creative professionals, medical specialists, and other recognized experts.
    32→
    33→The platform must be international from the beginning, with English as its primary language and an architecture that supports additional languages in the future.

    97→# 3. Technical Architecture & Technology Stack
    98→
    99→Use a modern TypeScript-based architecture.
   100→
   101→The recommended stack is:
   102→
   103→| Layer | Technology |
   104→|---|---|
   105→| Main Framework | Next.js |
   106→| UI Library | React |
   107→| Programming Language | TypeScript |
   108→| Styling | Tailwind CSS |
   109→| UI Components | shadcn/ui |
   110→| 3D Engine | Three.js |
   111→| React 3D Integration | React Three Fiber |
   112→| 3D Utilities | @react-three/drei |
   113→| UI Animations | Framer Motion |
   114→| Scroll Animations | GSAP + ScrollTrigger |
   115→| CMS & Admin | Payload CMS |
   116→| Database | PostgreSQL |
   117→| Geospatial Extension | PostGIS, when required |
   118→| Initial Search | PostgreSQL Full-Text Search |
   119→| Advanced Search | Meilisearch, when required |
   120→| Media Storage | Cloudflare R2 |
   121→| CDN | Cloudflare CDN |
   122→| Deployment | Vercel or suitable managed infrastructure |
   123→
   124→## Architectural Approach
   125→
   126→Use a **Modular Monolith** architecture.
   127→
   128→Do not introduce microservices, Kubernetes, or unnecessary infrastructure complexity in the initial implementation.
   129→
   130→The system should be modular, maintainable, and capable of evolving as the platform grows.
   131→
   132→Keep business logic, data access, API functionality, and presentation components logically separated.
   133→
   134→### Next.js
   135→
   136→Use Next.js App Router.
   137→
   138→Requirements:
   139→
   140→- Server-side rendering where appropriate.
   141→- Static generation for suitable editorial content.
   142→- Dynamic rendering for frequently updated content.
   143→- SEO-friendly public pages.
   144→- Dynamic professional profile routes.
   145→- Optimized image delivery.
   146→- API integration.
   147→- Proper loading and error states.
   148→
   149→Use server components by default and client components only where interactivity is required.
   150→
   151→### Payload CMS
   152→
   153→Use Payload CMS as the primary content management system.
   154→
   155→Integrate Payload with the Next.js application.
   156→
   157→Payload must manage:
   158→
   159→- Professional profiles.
   160→- Expertise categories.
   161→- Industries.
   162→- Countries.
   163→- Professional collections.
   164→- Editorial stories.
   165→- Featured-professional schedules.
   166→- User-submitted applications.
   167→- Media assets.
   168→- Administrative roles and permissions.
   169→
   170→Use Payload's PostgreSQL adapter.
   171→
   172→Build reusable collections, relationships, validation rules, access controls, and administrative workflows.
   173→
   174→The administration interface should be suitable for non-technical editorial staff.
   175→
   176→Do not build a separate administration frontend unless there is a clear requirement.
   177→
   178→### PostgreSQL
   179→
   180→Use PostgreSQL as the primary database.
   181→
   182→Design normalized and maintainable data relationships.
   183→
   184→Recommended main entities:
   185→
   186→- Users
   187→- Professionals
   188→- Countries
   189→- Cities
   190→- ExpertiseCategories
   191→- Industries
   192→- Collections
   193→- CollectionMembers
   194→- Stories
   195→- FeaturedSchedules
   196→- FeaturedApplications
   197→- MediaAssets
   198→
   199→Support many-to-many relationships where professionals belong to multiple expertise categories, industries, or collections.
   200→
   201→Use stable identifiers and appropriate indexing.
   202→
   203→### Geospatial Data
   204→
   205→Support geographic information for professionals.
   206→
   207→Recommended fields:
   208→
   209→- Country code.
   210→- Country name.
   211→- City.
   212→- Region.
   213→- Latitude.
   214→- Longitude.
   215→
   216→PostGIS can be introduced for advanced geographic queries, regional searches, and proximity-based discovery.
   217→
   218→Do not make PostGIS a mandatory dependency for simple country-level filtering.
   219→
   220→The globe must consume structured geographic data rather than hardcoded frontend information.
   221→
   222→### Search
   223→
   224→Initially use PostgreSQL Full-Text Search and indexed database queries.
   225→
   226→Search should cover:
   227→
   228→- Professional names.
   229→- Professional titles.
   230→- Expertise.
   231→- Industries.
   232→- Countries.
   233→- Collections.
   234→- Editorial stories.
   235→
   236→Keep the search architecture extensible so Meilisearch can be integrated later without redesigning the entire search experience.
   237→
   238→### Media Storage
   239→
   240→Use Cloudflare R2 for professional portraits, article images, and other uploaded media.
   241→
   242→Implement optimized image delivery, suitable formats, responsive image sizes, and CDN caching.
   243→
   244→Never store large media files directly inside the relational database.
   245→
   246→### ORM & Data Access
   247→
   248→Use Payload's database integration as the primary data-access layer.
   249→
   250→Avoid adding Prisma or another ORM unnecessarily.
   251→
   252→If independent application modules eventually require direct database access, introduce an additional data-access layer only when justified.

   336→## Section 2: Interactive 3D Global Globe
   337→
   338→Create a large, realistic, interactive 3D globe as the central visual identity of the homepage.
   339→
   340→Initially, position the globe behind and slightly to the left of the featured-professional card.
   341→
   342→### Globe Visual Design
   343→
   344→Match the SkilledSphere visual identity.
   345→
   346→Use:
   347→
   348→- Dark navy and deep blue oceans.
   349→- Subtle country boundaries.
   350→- Elegant geographic outlines.
   351→- Carefully selected gold highlights.
   352→- Subtle illuminated geographic markers.
   353→- Soft atmospheric lighting.
   354→- Sophisticated dark surroundings.
   355→
   356→Avoid cartoon-like earth graphics and excessive neon effects.
   357→
   358→The globe should rotate slowly and continuously when idle.
   359→
   360→Its movement should feel calm, elegant, and cinematic.
   361→
   362→### Scroll-Driven Globe Transition
   363→
   364→This is a critical interaction.
   365→
   366→Implement a coordinated scroll-based transition between the featured-professional hero and the global discovery experience.
   367→
   368→Initial state:
   369→
   370→- Featured card is prominent.
   371→- Globe is positioned behind the card.
   372→- Globe rotates slowly.
   373→
   374→As the user scrolls:
   375→
   376→1. The featured card gradually scales down.
   377→2. The card moves backward visually and fades away.
   378→3. The globe gradually increases in size.
   379→4. The globe moves into the foreground.
   380→5. The globe becomes the dominant visual element.
   381→6. The transition feels continuous and cinematic.
   382→
   383→Avoid excessive animation or interactions that make scrolling uncomfortable.
   384→
   385→Once the transition completes, the globe becomes fully interactive.
   386→
   387→### Interactive Country Selection
   388→
   389→Users must be able to interact directly with the globe.
   390→
   391→Required interactions:
   392→
   393→- Rotate the globe using mouse drag or touch gestures.
   394→- Zoom in and out where appropriate.
   395→- Click or tap a country.
   396→- Highlight the selected country.
   397→- Rotate the globe toward a selected country.
   398→- Display a country-specific professional discovery panel.
   399→
   400→When a country is selected, open a floating panel on the RIGHT side of the globe.
   401→
   402→The panel should contain:
   403→
   404→- Country name and flag.
   405→- Number of listed professionals.
   406→- Featured professionals from that country.
   407→- Professional portraits.
   408→- Names and professional titles.
   409→- Main expertise tags.
   410→- Short descriptions.
   411→- Links to individual profiles.
   412→- View All Professionals action.
   413→
   414→The panel must feel visually integrated with the globe environment.
   415→
   416→Do not make it look like a generic dashboard.
   417→
   418→### Geographic Data Management
   419→
   420→The globe must connect to structured professional data.
   421→
   422→Each professional record must contain geographic information.
   423→
   424→When an administrator adds a new professional and assigns a country, that professional should automatically appear in the corresponding geographic discovery results.
   425→
   426→Do not require manual editing of the 3D globe whenever a professional is added.
   427→
   428→Countries without listed professionals should remain selectable and display an elegant empty state.
   429→
   430→Use real geographic boundaries and country identifiers.
   431→
   432→### Country Navigation Ticker
   433→
   434→Directly below the globe section, create an elegant horizontal country navigation ticker.
   435→
   436→Example:
   437→
   438→United States · United Kingdom · Germany · France · Canada · Japan · Singapore · Australia · Switzerland
   439→
   440→When users click a country:
   441→
   442→- The globe smoothly rotates toward that country.
   443→- The selected country becomes highlighted.
   444→- The professional panel opens.
   445→- The country ticker reflects the active selection.
   446→
   447→Support manual horizontal scrolling.
   448→
   449→The ticker should feel like part of the visual experience rather than a conventional navigation menu.
   450→
   451→### Leaving the Globe Section
   452→
   453→As the user continues scrolling:
   454→
   455→- The globe gradually scales down.
   456→- It moves backward and fades away.
   457→- The country ticker disappears.
   458→- The next homepage section enters naturally.
   459→
   460→Use coordinated scroll animations.
   461→
   462→The globe must not remain fixed indefinitely or interfere with subsequent sections.

   893→Use:
   894→
   895→**GSAP + ScrollTrigger**
   896→- Scroll-based globe transitions.

   900→
   901→**Framer Motion**
   902→- UI component transitions.
   903→- Card interactions.
   904→- Modal and panel transitions.

   908→**Three.js / React Three Fiber**
   909→- Globe rotation.
   910→- Camera positioning.
   911→- Geographic visualization.
   912→- Lighting and materials.
   913→- Interactive country selection.

   915→Do not let GSAP and Framer Motion simultaneously control the same animated properties of an element.
